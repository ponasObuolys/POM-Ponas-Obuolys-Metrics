# POM 2.4.1: Grok Bot and Cursor limits refresh while Cursor is closed

**Download `POM-2.4.1.dmg` below. Requires macOS 14+; Apple silicon and Intel.**

In 2.4.0 the Grok Bot and Cursor limits refreshed only while the Cursor app was open.

- Read the Cursor sign-in after Cursor quits. Cursor keeps it in a SQLite database in WAL mode; once the app closes, the database's shared-memory file is gone and POM's read-only connection could no longer open it. POM now reads the settled file as immutable in that case. This was the cause of the stalled readings.
- Use Grok Bot's own sign-in for the Grok Bot limit, with Cursor's as a stand-in for the same account only. The Grok Bot card no longer depends on Cursor being installed or signed in. macOS asks once for access to **Grok Bot Safe Storage**; if you decline, POM keeps using the Cursor sign-in.
- Check a sign-in's expiry before sending it. When every local sign-in has lapsed, POM sends nothing, keeps the last reading with its real age (or a newer one saved by Grok Bot itself) and resumes as soon as either app renews its sign-in. POM never renews a sign-in itself: the renewal key is single-use and bound to the owning app.
- Identify an account by the token's subject rather than the token, so a renewed token no longer clears the card for a moment.

## Validation

450 core checks and the SwiftUI rendering/integration checks passed, including a WAL database without its shared-memory file, the Grok Bot secret-store layouts, session choice between the two apps and the lapsed-sign-in state.

A live check on 2026-11-25 with Cursor and Grok Bot both closed: before the fix the Cursor sign-in could not be read; after it both sign-ins were read, matched the same account, and the server returned the weekly Grok Bot limit. The check printed expiry times and the percentage only.
