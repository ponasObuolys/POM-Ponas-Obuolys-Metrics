# POM 2.3.1 — Claude weekly-only limits

Local development update for macOS 14+, Apple silicon and Intel. Public release assets have not been published.

- Accept Claude usage responses without a five-hour session limit, including omitted and null session fields. Weekly usage continues refreshing instead of rejecting the response and retaining stale readings.
- Hide absent session meters in the dashboard and menu bar, and skip their alerts and history readings. Accounts that still report a session limit retain their meter.
- Preserve weekly-only responses through the local cache and Claude Code status-line bridge.
- Recognize the Ultra subscription name when reported by Claude.
- Allow explicit SDK and build-system overrides for local packaging and UI checks.

Anthropic documents that verified Ultra accounts (formerly Max 20x) no longer have a five-hour limit. Other accounts can still have one; POM follows the reported windows rather than inferring limits from the plan name. See [Anthropic’s Ultra plan documentation](https://support.claude.com/en/articles/17728952-what-is-the-ultra-plan).

Validation: 341 core checks, five bridge tests, and SwiftUI rendering/integration checks, including a weekly-only Claude card, all 31 service selections and five pinning variants. The universal arm64/x86_64 bundle passed signature and property-list checks. This Mac uses the installed macOS 26.5 SDK because its default 27.2 SDK requires an unavailable SwiftUI macro plugin.

This version includes the [2.3.0 dashboard and provider integrations](2.3.0.md). Local development bundles are ad-hoc signed and are not Apple-notarized.
