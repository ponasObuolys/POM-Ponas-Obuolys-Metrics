# POM 2.2.1 — daily token history

Development build; public release remains pending Developer ID signing and Apple notarization.

- History now has two series: Claude and Codex daily token counts, with 7/30-day totals across models. Quota resets no longer reset history values.
- Claude Code usage comes from local sessions, including subagents; web and other Macs are excluded. Input/output/cache counts are deduplicated by message ID.
- Codex account usage comes from `account/usage/read`. Unsupported versions show unavailable data, retaining a clearly labelled cache.
- History updates every 15 minutes. Local imports run in small background batches and resume from durable file offsets. Unchanged logs are not reread.
- Provider logos and source coverage appear in the history cards. LT/EN interfaces include import, stale-cache and incomplete-record states.
- No extra package, permanent process or analytics service. SQLite is supplied by macOS. Legacy quota history is left untouched and no longer used.

Resource check on the development Mac: 646,768,917 transcript bytes, 24,528 unique
assistant message IDs, 25 retained days. Cold import without throttle: 7.23 s wall
time, 50.4 MB peak RSS (39.8 MB peak memory footprint). An unchanged refresh: 0 bytes
of transcript content, 0.09 s including metadata discovery. A separate full-file
reference calculation produced identical daily sums. These are measurements on one
Mac, not a guarantee for every machine. The app adds 0.5 s quiet intervals between
batches (2 s in Low Power Mode), so first import takes several minutes.

Claude days use UTC. Codex date-only buckets remain as supplied because the API
provides no timezone metadata. Today's counts are partial. Totals describe tokens,
not billing amounts; source coverage differs between the providers.

Validation: 244 local checks (252 with live Claude/Codex responses), four bridge
integration tests, LT/EN SwiftUI renders including 7/30 days, universal release
compilation, strict bundle signature verification and mounted DMG contents checked
against the installed 2.2.1 executable. The DMG is a development build, not notarized.
